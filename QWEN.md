# QWEN Project Context

## Project Overview

This project is **Ensō**, a PHP8 micro-framework designed for building fast, lightweight REST or asynchronous services. It leverages modern PHP (8.1+), strict PSR standards, and integrates components from Yii3 and other PSR-compatible libraries. The framework is containerized with Docker and supports multiple runtime adapters: FPM (Nginx), Swoole, RoadRunner, and CLI. It is suitable for both web and CLI applications, with a focus on extensibility, performance, and developer ergonomics.

### Key Features
- Multi-environment setup via Docker Compose
- Supports Swoole and RoadRunner for high-performance, long-running processes
- Strict PSR compatibility (DI, Logger, Cache, HTTP, Middleware, etc.)
- MySQL/PostgreSQL and Redis integration
- CLI and HTTP API endpoints share the same application logic
- Codeception for unit, REST, and E2E testing
- Autogenerated OpenAPI (Swagger) and PhpDoc documentation
- Extensible middleware and routing system

## Architecture
- **Core:** `Enso\Enso` is the main application class, handling configuration, DI, middleware, and request/response lifecycle.
- **Entry Point:** `enso-psr/entrypoint.php` creates the application instance, determines runtime (CLI, Web, Swoole), and dispatches requests.
- **Routing:** Configured in `enso-psr/config/routing.php`, mapping routes to action handlers (e.g., `IndexAction`, `TelegramAction`).
- **Actions:** Located in `enso-psr/Application/`, each action (e.g., `IndexAction`, `TelegramAction`) implements business logic for a route.
- **Models:** Example: `Application/Model/User.php` (ActiveRecord pattern).
- **Services:** Example: `Application/Service/Telegram.php` (Telegram API integration).
- **Testing:** Codeception configuration in `enso-psr/codeception.yml`.

## Building, Running, and Testing

### Prerequisites
- Docker and Docker Compose

### Setup
1. Edit `.env` or ensure `enso.localhost` is in your system hosts file.
2. Build and start all services:
   ```sh
   docker-compose up -d --build
   ```
3. Check running containers:
   ```sh
   docker-compose ps
   ```

### Endpoints
- **Nginx + FPM:** `http://enso.localhost/(index|open-api)`
- **Swoole:** `http://enso.localhost:81/(index|open-api)`
- **RoadRunner:** `http://enso.localhost:82/(index|open-api)`
- **Swagger UI:** `http://enso.localhost:8080/`
- **Docs:** `http://enso.localhost:(80|81|82)/docs`

### CLI Usage
- Run application logic via CLI:
  ```sh
  docker-compose exec php ./enso default/open-api
  docker-compose exec php ./enso default/open-api > ./open-api.json
  ```

### Testing
- Build and run tests:
  ```sh
  docker-compose exec php vendor/bin/codecept build
  docker-compose exec php vendor/bin/codecept run
  docker-compose exec php-sw vendor/bin/codecept run
  ```
- Coverage:
  ```sh
  docker-compose exec php vendor/bin/codecept run --coverage-html
  ```

### Documentation
- Generate PhpDocs:
  ```sh
  ./generate-docs.sh
  # or
  docker run --rm -v $(pwd):/src phpdoc/phpdoc -d /src/enso-psr  -i vendor -t /src/enso-psr/docs/phpdoc
  ```

## Development Conventions
- **Coding Style:** Modern PHP (8.1+), PSR-12, strict typing, namespaces, and autoloading via Composer.
- **Testing:** Codeception for all test types. Tests are in `enso-psr/Tests/`.
- **Configuration:** Environment variables in `.env` and `.env.example`. Routing in `config/routing.php`.
- **Dependency Management:** Composer (`composer.json`, `composer.lock`).
- **Contribution:** Follow PSR standards, use DI, and prefer middleware for cross-cutting concerns.
